# 收藏 busy 请求的分段诊断

## 结论

本次在 `e7a1203360a0` 上分别运行普通构建和临时诊断构建，均未复现此前收藏 p95 3.509875ms。诊断构建中实际出现的 3.8ms 尾部样本主要等待 Library writer；线程排队及该请求自己的事务、COMMIT 较短。这个结果解释本次尾部样本，不能追溯证明原相对门失败的原因，也不能将原失败改为通过。

没有据此调整锁、SQLite 策略、性能门或资源上限，也没有将临时观测代码加入产品。

## 运行与准入

两轮使用相同的停止态夹具，保持原 166 项请求顺序和 busy 扫描准入。每项在循环边界增加 30 秒诊断软限时；缓存准备及单次完整请求可能超过该时间。达到限时后保留已采集的状态、失败及不足样本，继续下一项。该变化影响前序负载时长，两轮均明确为诊断，不能作为正式全量基线。

普通构建在前，诊断构建在后。两轮的产品、二进制、启动器、工具、业务数据和来源快照分别绑定摘要；重新运行离线业务 oracle，50 个用户的期望与原冻结夹具一致。工具的业务准入、全部 166 项执行及业务验证完成；两轮 gate 实际退出均为 1，诊断协调器均退出 0。部分前序用例不足 200 样本的失败保留。

收藏每轮均取得 200 次 HTTP 200、响应合同通过，无被排除的窗口样本。每次唯一请求 ID 与服务端回显一致；相邻两次扫描观察均为同一 operation 的 running。该观察不标识扫描内部阶段，也不证明请求期间每个瞬间都处于 running。

## 本次尾部归属

诊断构建中采样的 200 个收藏请求各与一条服务端观测匹配。计时在实际 blocking worker 和 Library writer 内采集，日志在 writer 释放后输出，不记录凭据、请求正文、用户或 Media 标识。

| 本次客户端耗时 | writer 等待 | 自有事务 | 其中 COMMIT | blocking 排队 |
|---|---:|---:|---:|---:|
| 3.868208ms | 3.356458ms | 0.255166ms | 0.056708ms | 0.003541ms |
| 3.831917ms | 3.373292ms | 0.194291ms | 0.042667ms | 0.005208ms |

全部样本的 writer 等待 p95 为 0.654333ms，自有事务 p95 为 0.321875ms，COMMIT p95 为 0.056708ms，blocking 排队 p95 为 0.005084ms。事务、COMMIT、writer 持有和 SQL 计时存在嵌套，不能相加；各自分位数也不代表同一请求。SQLite PROFILE 的毫秒粒度不能分解这些亚毫秒事务。

本次没有关联竞争 writer 的具体业务操作，不能进一步归因于扫描中的某个阶段。原完整 busy 比较的 0.951917→3.509875ms 相对失败仍保留，最终受影响的正式复测另记。

## 失败、隔离和证据

首个控制轮因工具摘要与旧业务绑定不匹配，在请求用例前被拒绝；更正目录布局前的 oracle 也曾失败。随后一次未加软限时的诊断在推荐请求持续超时后，由父任务向已核验的自有 gate 发送 SIGINT：stage 退出 -2、协调器退出 2，没有收藏样本。这些准备失败和部分运行不记为通过。

最终两轮均独立复制数据库和 STRM 夹具；原 app/sidecar、真实 STRM 与 pan 来源清单前后一致，自有 listener、owner 和 live 副本均已清理。原始回执分别为 `favorite-control-20261106T045711Z`、`favorite-instrumented-20261106T050236Z`，位于 `/private/tmp/crawler-perfgate-matched-candidate-1c3af0236c14/retests/`；汇总为 `/tmp/crawler-favorite-diagnostic-e7-summary.json`。

临时观测有公开 Router 的实际失败→通过验证；它只证明诊断字段能够在真实请求中产生。未为本项重跑 workspace、真实 491 来源、GUI、容量或内存，既有结果保持各自版本与范围。
